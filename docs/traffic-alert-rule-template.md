# 流量统计告警规则模板

> 流量进度条的数据来源。**每台要显示流量进度条的服务器，都需要一条启用的流量统计规则**，规则里没有的服务器前台不会显示进度条。
>
> 字段说明来源：[哪吒官方文档 · 通知设置](https://nezha.wiki/guide/notifications.html)

## 添加位置

后台 → **告警** → **新增规则**，按下面表单逐项填。

## 表单字段说明

| 表单字段 | 作用 | 怎么填 | 示例 |
|:---------|:-----|:-------|:-----|
| 名称 | 规则名字，仅用于识别 | `流量统计 · 服务器名` | `流量统计 · US` |
| 类型 | 监控类型。`transfer_all_cycle` = 周期内双向流量总和（入站+出站）；还有 `transfer_in_cycle`（入站）、`transfer_out_cycle`（出站） | 选 `transfer_all_cycle` | |
| duration | 采样记录数（必须 ≥3）。面板约每 3 秒采样一次，窗口 ≈ duration×3 秒；窗口内超过 70% 的样本超限才触发，防止瞬时波动误报 | `10`（约 30 秒窗口） | |
| min | 触发下限（字节）。低于该值触发；`0` 表示不设下限 | `0` | |
| max | 触发上限（字节）。流量超过该值触发，同时作为前台进度条的 100% 基准 | 配额 GB × 1073741824 | 1.2TB = `1288490188800` |
| cover | 服务器范围策略。`0` = 监控所有服务器（用 ignore 排除）；`1` = 忽略所有服务器（用 ignore 指定要监控的） | 选 `1（忽略所有，选择特定服务器）` | |
| 服务器ID | 配合 cover 指定要监控的服务器，格式 `{"服务器ID": true}`，可多个 | `{"4":true}` | `{"1":true,"2":true}` |
| cycle_start | 计费周期起始时间（RFC3339 格式）。填服务商计费日，如每月 15 号计费就填当月 15 号 | `2026-04-28T00:00:00+08:00` | |
| cycle_interval | 每隔多少个周期单位统计一次 | `1`（每 1 个月） | |
| cycle_unit | 统计周期单位：`hour` / `day` / `week` / `month` / `year` | 月流量选 `month` | |
| 通知组 | 告警发送到哪个通知组（飞书/邮件等渠道的集合） | 默认通知组 | |
| 触发模式 | `仅一次` = 状态变化时通知一次（正常→超限 或 超限→恢复）；`始终触发` = 每次检查满足条件都通知 | 选 `仅一次` | |
| 告警时要触发的任务 | 告警触发时执行的任务 ID，英文逗号分隔；不需要就留空 | `1,2,3` | |
| 恢复后要触发的任务 | 告警恢复时执行的任务 ID，英文逗号分隔；不需要就留空 | `1,2,3` | |
| 启用 | 勾选后规则生效，前台才显示流量进度条 | 勾选 ✅ | |

## max 字节换算表

| 配额 | 字节数 |
|:-----|:-------|
| 100GB | `107374182400` |
| 150GB | `161061273600` |
| 500GB | `536870912000` |
| 1TB | `1099511627776` |
| 1.2TB | `1288490188800` |
| 2TB | `2199023255552` |

## 高级 JSON（表单自动生成，一般不用手填）

填完表单，底部的"高级 JSON"会自动生成，结构如下：

```json
[{
  "type": "transfer_all_cycle",
  "max": 1288490188800,
  "cycle_start": "2026-04-28T00:00:00+08:00",
  "cycle_interval": 1,
  "cycle_unit": "month",
  "duration": 10,
  "cover": 1,
  "ignore": {"4": true}
}]
```

保存后，前台对应服务器卡片下方就会出现流量进度条。
